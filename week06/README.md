# 第六周：ETTh1 油温单步预测

使用最近 24 小时的变压器油温 `OT` 预测下一小时的 `OT`。每小时获得新的真实观测后，再做下一次预测。`HUFL` 仅用于事后画图观察，没有进入任何预测模型。

## 数据与环境

`data/ETTh1.csv` 取自 [ETDataset 官方仓库](https://github.com/zhouhaoyi/ETDataset/blob/main/ETT-small/ETTh1.csv)。原文件有 17,420 行，时间为 2016-07-01 00:00 至 2018-06-26 19:00；正式实验使用前 14,400 小时。日期逐小时递增、无重复，使用的 `OT`、`HUFL` 无缺失或非有限数值。读取时解析 `date`；输入只用历史 `OT`，预测目标是下一小时的 `OT`。

实际运行环境：Python 3.13.5、NumPy 2.1.3、pandas 2.2.3、Matplotlib 3.10.0、scikit-learn 1.6.1。安装方式：

```powershell
python -m pip install -r requirements.txt
python run_windows.py
python run_baselines.py
```

在 `week06` 目录执行这两个入口；无需 GPU。`requirements.txt` 记录所用版本。

## 文件职责与调用

`run_windows.py` 和 `run_baselines.py` 负责设置参数、按顺序调用组件；导入组件不会自动执行实验。`data.py` 读取并检查时间序列、构造窗口、按目标时刻分组；`models.py` 实现两个固定规则和标准化后拟合的线性/Ridge 模型；`evaluation.py` 计算 MAE、RMSE 并从逐行预测复核汇总；`reporting.py` 接收现成记录，保存 CSV 与绘制 PNG。

## 实践一：窗口核对

前 12 小时的油温从 00:00 的 30.531 降到 05:00 的 21.174，但 06:00 回升至 22.792，并非单调下降。`make_windows(series, L)` 对每个目标下标 `t` 构造 `X=series[t-L:t]`、`y=series[t]`；输入由旧到新，最末值对应目标前一小时。

- `L=3`：`X` 为 `(9, 3)`，首条输入 00:00–02:00 的 `[30.531, 27.787, 27.787]`，目标 03:00 的 `25.044`；末条输入 08:00–10:00，目标 11:00。
- `L=5`：`X` 为 `(7, 5)`，首条输入 00:00–04:00，目标 05:00；末条输入 06:00–10:00，目标仍是 11:00。

因此长度 `N` 的连续序列可生成 `N-L` 条下一小时样本。窗口变长增加每条样本的历史特征数，却使最早可预测时刻后移。`results/window_examples.csv` 共 16 行，`input_start`、`input_end` 和 `target_index` 均是原 CSV 的零基下标；`target_time` 与 `target_value` 来自目标行，`input_values` 是历史数值的列表文本。例如 `L=3, target_index=3` 的三个输入下标为 0–2，目标在下标 3。

## 实践二：划分、模型与调参

固定 `L=24`、单步目标。窗口在前 14,400 小时上一次性构造，再按目标时刻分组：训练为 2016-07-01 至 2017-06-26 00:00 前，验证为其后至 2017-10-24 00:00 前，测试为其后至 2018-02-21 00:00 前，样本数依次为 8616、2880、2880。第一条验证样本的输入跨入训练时段：2017-06-25 00:00–23:00，目标是 2017-06-26 00:00；第一条测试样本使用 2017-10-23 全天真实观测，目标是 2017-10-24 00:00。每次预测只读取目标前已经观测到的 24 个点。若一次性提前预测整个测试时段，就无法使用测试时段内后来才出现的真实油温，本实验的逐小时更新场景不适用于那种任务。

四种方法中，`last_value` 直接取窗口最后一项，`window_mean` 取 24 个历史点的平均；两者无需拟合。`lag_linear` 与 `ridge_tuned` 在训练窗口上拟合 `StandardScaler` 和回归器组成的管道，验证、测试只用已拟合管道预测，目标保持原始油温尺度。24 列依次表示由旧到新的 24 个滞后观测；线性权重是统计拟合结果，不是设备传热参数。

我选择 Ridge 路线以观察对 24 个滞后权重增加 L2 约束的效果。候选 `alpha=0.1、10、1000` 跨越弱、中、强三个量级。每个候选单独在相同训练样本上拟合，并以完整验证集 RMSE 选择；若完全相同则取较小值。三者验证 RMSE 分别为 **0.910179、0.912002、1.218373**，选定 **`alpha=0.1`**。普通滞后线性回归的验证 RMSE 为 0.910183。强约束使训练与验证误差都明显上升；若继续实验，可在 0.01–1 附近细分候选，并用多个顺序向前的验证时段检验极小差异是否稳定。

完整验证集四种方法的 RMSE：`last_value=0.925271`、`window_mean=1.879948`、`lag_linear=0.910183`、`ridge_tuned=0.910179`。按验证 RMSE 与规定顺序选择 `ridge_tuned` 为最终方法；其测试 RMSE 为 **0.584526**。该选择相对普通线性回归的优势约 0.000004，几乎可忽略，不宜解释为稳定的实际改进。测试集只在候选和方法确定后用于评价。

普通线性回归训练 RMSE 1.043134 最低，弱 Ridge 的验证 RMSE 0.910179 最低，差异极小。`alpha=1000` 的训练/验证 RMSE 为 1.488241/1.218373，两边一起恶化，提示此配置约束过强、偏欠拟合。这里没有明显的“训练特别好而验证显著差”的典型过拟合迹象；各配置的验证误差甚至小于训练误差，不同时段的油温水平、波动和工况变化可能影响难度。单次时间划分不足以断定泛化规律，应进一步检查按时间滚动的多个验证时段、残差分布和运行条件。

## 一段实际预测：观察、预测、解释

2017-06-26 00:00–07:00，实测油温从 20.963 逐步降至 18.642；`HUFL` 从 10.851 先降至 03:00 的 8.975，之后又波动回升，变化并非全程同步。对 03:00 的目标（原表下标 8643），实测 `OT=19.908`，最近观测预测 20.119，窗口均值预测 21.201，滞后线性回归预测 20.140，选定 Ridge 预测 20.141；四种方法在该时刻都偏高。窗口均值包含较早的较高油温，所以下降过程中滞后更明显。较早热量积累及温度响应延迟与这种现象相容，但负载、环境和冷却状态等因素并未全部输入，图上同向或不同向的变化都不能证明原因，也不能凭一次误差认定设备故障。

完整验证集指标概括较长时段的平均误差，首周图显示局部上升、下降与转折处的偏差。图中的每个点都可以按 `target_time` 在预测表定位到 `target_index`、真实值和四种预测值。
