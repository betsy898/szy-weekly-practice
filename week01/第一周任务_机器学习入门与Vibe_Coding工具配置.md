# 第一周任务：机器学习入门与 vibe coding 工具配置

## 一、本周目标

1. 理解机器学习的基本概念，能够结合具体例子解释常用术语。
2. 搭建适合自己的 vibe coding 工作流，能够使用 AI 工具辅助编程、运行和修改代码。
3. 完成一个数据读取与绘图小任务，把知识点与实际代码联系起来。

## 二、知识点理解

可以通过教材、课程、文档或与 AI 对话学习。重点是形成自己的理解，能够结合例子说明，而不只是记住定义。

| 知识点 | 需要理解的问题 |
|---|---|
| 机器学习 | 什么是从数据中学习规律？与直接编写固定规则有什么区别？ |
| 监督学习与无监督学习 | 是否有明确的标签？各能解决什么问题？强化学习了解大致含义即可。 |
| 回归与分类 | 预测连续数值与预测类别有什么区别？为什么不能仅凭标签是否写成数字判断？ |
| 样本、特征、标签 | 一条数据代表什么？模型输入哪些信息？希望预测什么？ |
| 模型与参数 | 模型怎样把输入变成输出？训练过程中哪些量会被调整？ |
| 训练与预测 | 学习参数与使用模型处理新数据有什么区别？ |
| 损失函数与评价指标 | 怎样指导模型学习，怎样判断表现？两者有时能否使用同一种量？ |
| 训练集、验证集、测试集 | 分别有什么用途？为什么需要区分？ |
| 泛化与过拟合 | 为什么训练数据上表现好，不代表新数据上也好？ |

尝试联系铁路项目思考：“预测下一次检测的某个数值”和“判断一段波形属于哪一类”分别是什么任务？各自的样本、特征和标签可能是什么？

## 三、实践任务

### 实践一：搭建 vibe coding 工作流

**没有对所有人都最好的工具，要找到最适配自己的。** 综合考虑自己的设备、操作习惯、使用频率、价格和额度，选择一种工具实际配置并使用。已有合适工具可以继续用，不要求统一品牌或购买订阅。

可以了解 Codex、Claude Code、Antigravity 或其他 AI 编程工具（比如vs code的插件copilot）。查阅另一种候选的功能与费用说明作简单比较即可，不要求同时安装或付费试用。阿里，kimi等也有自己的类似工具和coding plan。也可以接入deepseek，GLM等其他模型。

价格和额度以使用时的官方说明为准。选择时想清楚：自己每周大约使用几次，现有权益是否够用，订阅或按量付费是否适合自己的预算。先形成初步选择，后续可以根据实际体验调整。

完成以下工作：

1. 按官方说明安装客户端或插件，完成登录或模型接入配置。本周不要求在本机部署大语言模型。
2. 新建练习目录，准备可用的 Python 环境，安装 `pandas`、`matplotlib` 和 `scikit-learn`。已有可用环境可以复用。
3. 使用工具辅助完成实践二，经历“提出任务 → 查看代码 → 运行 → 检查结果 → 修改后再运行”的完整流程。
4. 学会查看代码改动，并通过 Git 或保留修改前副本恢复先前版本。（Git的使用非常重要！！！）

在学习笔记中简单记录选了什么工具、为什么适合自己，以及配置和使用中遇到的问题即可。

### 实践二：数据读取与绘图

统一使用 scikit-learn 自带的 diabetes 回归练习数据集，便于交流，也为下一周的线性回归练习做准备。数据说明见 [官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_diabetes.html)。

使用原始特征，可从以下代码开始：

```python
from sklearn.datasets import load_diabetes

dataset = load_diabetes(as_frame=True, scaled=False)
df = dataset.frame
```

这是表格回归数据，不是时序数据，不能把行号当作时间。本周先认识数据，不要求训练模型。

用一个 Python 脚本或 Notebook 完成：

1. 查看行列数、列名和前几行，指出哪些列是特征、哪一列是目标。
2. 统计各列缺失值，查看数值列的基本统计；没有缺失也如实记录。
3. 绘制目标值分布图，以及一个特征与目标的散点图，标明横纵轴含义并保留结果。
4. 做一次有明确目的的小修改，例如更换散点图的特征或调整直方图分箱数。先想一想预期变化，再运行检查。
5. 解释从数据加载到图形输出的主要步骤，记录一项观察，以及一个不能仅凭这些图得出的结论。

可以让 AI 辅助写代码和调试，但要能解释关键步骤与自己的修改。理解方法和实现，才能开展合理的创新与改进。

## 四、提交内容

本周提交两部分，尽量在当周完成，并在飞书共享记录中提供文件或链接。遇到困难或预计延期时及时反馈。

**1. 一份报告或学习笔记**

没有格式要求，也不要求固定篇幅，记录自己的理解和学习过程即可。可以包含对知识点的认识、工具选择理由、实践中的发现、代码修改、遇到的问题及仍不理解的地方。图表可以直接放在笔记中，不需要按模板逐项填写。

**2. 实践代码**

提交实际运行过的脚本或 Notebook，以及必要的结果文件。**以后每次提交代码，都要附带 README 和依赖说明，方便别人阅读和复现。**

- README 说明代码做什么、数据从哪里来、主要文件的作用、如何安装环境和运行，以及结果保存在哪里。
- 依赖可以放在 `requirements.txt` 中，也可以直接写在 README 中；写清 Python 版本、所需库及实际使用的版本，并提供安装方法。
- 提交前按自己的 README 重新运行一遍，确认必要文件齐全，别人能够按说明复现主要结果。
