# 第二周任务：线性回归与 GitHub 代码管理

## 一、本周目标

1. 理解线性回归、损失函数和梯度下降的基本思想，区分模型训练与效果评价。
2. 用 NumPy 实现单特征线性回归的梯度下降，与均值基线和库函数求解结果比较，完成预测与误差分析。
3. 学习 Git 与 GitHub 的基本使用，建立本学期固定的公开代码仓库，将第一周和第二周实践按文件夹整理并提交。

可以继续使用 vibe coding 工具，但要能解释关键代码和实际结果。重点是理解流程，任务量尽量控制在一下午可以完成的核心实践范围内。

## 二、知识点理解

| 知识点 | 需要理解的问题 |
|---|---|
| 线性回归 | `预测值 = 权重 × 特征 + 截距` 表示什么？多个特征时怎样组合？权重与截距是怎样得到的？ |
| 误差与损失 | 预测值与真实值之间的误差如何计算？为什么常用误差平方的平均值，也就是 MSE，作为回归损失？ |
| 梯度下降 | 梯度为什么能帮助确定参数更新方向？学习率过大或过小可能怎样影响训练？能否用简单数值解释一次更新？ |
| 数据划分 | 训练集、验证集、测试集分别做什么？为什么不能先用全部数据训练，再拿其中一部分评价泛化效果？ |
| 评价指标 | MAE、RMSE 分别表示什么？数值越大还是越小更好？哪个对少数较大误差更敏感？ |
| 基线与泛化 | 如果总是预测训练集目标的均值，表现会怎样？训练误差低，是否一定意味着对新数据预测得好？ |
| Git 与 GitHub | 本地版本管理与远程代码托管有什么区别？仓库、暂存、commit、push、pull 和 clone 分别有什么作用？为什么 commit 后网页上的代码可能还没更新？ |

梯度下降要结合下面的小实验理解，不要求编写通用训练框架。scikit-learn `LinearRegression` 求解普通最小二乘问题，本周将它作为对照，检查自己实现的梯度下降是否得到接近的结果；不能把调用它的 `fit()` 自动理解成“执行了梯度下降”。可查阅 [LinearRegression 官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LinearRegression.html)。

## 三、实践任务

### 实践一：建立本学期 GitHub 仓库

**每个人使用一个固定的公开 GitHub 仓库，整个学期的组会实践都放在这个链接下，每周一个文件夹。** 不需要每周新建仓库，也不需要把四个人的代码合并到同一个仓库。

1. 注册或登录 GitHub，创建一个公开仓库，名称自定，例如 `ml-weekly-practice`。已有适合的仓库也可以继续使用。
2. 将仓库克隆到本地，创建 `week01` 和 `week02` 文件夹。将第一周的代码、README、依赖说明和必要结果补充到 `week01`；本周内容放在 `week02`。
3. 完成一次“修改文件 → 查看差异 → 暂存 → commit → push”的流程。可以使用命令行、编辑器的 Git 界面或 GitHub Desktop，但要理解每一步的作用。
4. 再做一次小修改，例如补充运行说明，提交并推送，然后在 GitHub 网页确认文件及提交记录已经更新。学习查看提交历史，并理解以后怎样通过 pull 获取远程更新。
5. 在仓库根目录的 README 中列出每周任务名称及对应文件夹链接，方便大家从同一个入口查看。

建议结构如下，脚本名称可以自行安排，使用 Notebook 也可以：

依赖也可以写在各周 README 中，此时不必另建 `requirements.txt`。用 `.gitignore` 排除虚拟环境、缓存和本地配置。公开仓库不上传密码、API key 或未经允许公开的铁路项目数据。

入门可以参考 [GitHub 官方教程](https://docs.github.com/en/get-started/using-github/hello-world)。本周先掌握上述基本流程，分支与 Pull Request 可后续再练习。

### 实践二：单特征梯度下降与模型评价

继续使用第一周的 diabetes 数据，通过 `load_diabetes(as_frame=True, scaled=False)` 读取原始特征，**本周必做部分只使用 `bmi` 一个特征**，拟合 `预测值 = w × x + b`。把问题缩小，重点观察参数怎样通过训练发生变化。

1. **划分数据。** 将数据随机划分为约 60% 训练集、20% 验证集和 20% 测试集，固定随机种子，例如 `42`。可以先留出 40%，再将这部分均分为验证和测试；所有模型使用同一份划分。此次是表格回归练习，不能直接将这种随机划分照搬到未来的时序任务。
2. **标准化特征。** 只用训练集的 `bmi` 计算均值和标准差，将训练、验证和测试特征按同一组统计量变换。目标值保持原样。思考为什么不能分别对三部分拟合标准化参数，也不能先对全部数据拟合再划分。
3. **建立简单基线。** 只用训练集目标值计算均值，对每条输入都预测这个均值。可以自行实现，也可以使用 `DummyRegressor(strategy="mean")`。思考：这个模型完全不看特征，为什么仍值得比较？参见 [官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.dummy.DummyRegressor.html)。
4. **用 NumPy 实现梯度下降。** 从 `w = 0`、`b = 0` 开始，每轮使用全部训练样本计算预测、MSE 和梯度，再同时更新两个参数。保存每轮训练损失，能够指出代码中预测、计算梯度和更新参数分别是哪一步。不用自动求导库，也不以调用现成优化器代替这一小段实现。
5. **比较学习率。** 使用相同初始化和迭代次数，分别尝试两个学习率，例如 `0.01` 和 `0.1`，各训练 500 轮，将损失曲线画在同一张图上。观察下降速度和最终损失；这两个学习率不一定会发散，不要为了得到预设结论修改结果。解释学习率更大是否总是更好。
6. **与库函数对照。** 在同一份标准化后的单特征训练数据上拟合 `LinearRegression`，比较它与梯度下降的权重、截距、训练 MSE 和预测值。梯度下降充分收敛时，两者应接近；不接近时检查梯度、数据形状、迭代次数和学习率，不能要求有限步结果完全相等。
7. **评价泛化效果。** 输出均值基线、两组梯度下降结果及库函数模型在训练集、验证集上的 MAE、RMSE。依据训练过程和验证结果确定梯度下降配置，再对均值基线、选定的梯度下降模型和库函数模型计算测试指标，不根据测试分数反复调整方案。保存比较表，可使用 CSV 或 Notebook 输出。
8. **检查预测。** 为选定的梯度下降模型绘制测试集“真实值与预测值”散点图，加入 `y = x` 参考线。核对几条样本的真实值、预测值和误差，准备解释训练损失下降为什么不等于对新数据预测一定准确。

梯度计算可以参考以下关系，其中 `mean` 表示对训练样本求平均，`error = w × x + b - y`：

```text
MSE = mean(error²)
dw = 2 × mean(error × x)
db = 2 × mean(error)
w_new = w - learning_rate × dw
b_new = b - learning_rate × db
```

同一轮的两个梯度都根据更新前的参数计算。注意 NumPy 数组形状，避免把一维目标与二维预测相减，意外得到一个矩阵。

可以用 AI 辅助实现，但要能解释为什么这样更新、学习率控制什么，以及曲线是否符合自己的理解。**使用全部特征训练线性回归改为选做**，完成上述单特征实验即可，不要求额外调参或达到指定分数。
